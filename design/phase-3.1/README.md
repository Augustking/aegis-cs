# 阶段 3.1 离线双端原型

所有人物、工单、评分、事件与回复均为虚构。仅用于评审，不是实际客服；请勿输入真实个人信息。无依赖安装、无模型 API、无业务接口、无数据持久化。

## 运行

推荐只托管此原型目录，不运行 Flask、LangGraph 或 Vite。

```powershell
python -m http.server 8031 --bind 127.0.0.1 --directory "E:/mye盘项目/jianli project/customer-service-ai-agent/design/phase-3.1"
```

人工在浏览器打开下列地址（交付过程中未使用浏览器工具）：

- 客户咨询：`http://127.0.0.1:8031/index.html#/chat`
- 演示登录：`http://127.0.0.1:8031/index.html#/agent/login`
- 坐席处理台：`http://127.0.0.1:8031/index.html#/agent/inbox`
- 只读复盘：`http://127.0.0.1:8031/index.html#/agent/review`

Ctrl+C 停止静态服务器。也可尝试直接双击 index.html；个别浏览器的 file 协议 / CSP 策略可能限制本地脚本，此时使用上述 localhost 静态服务。不要为此放宽业务安全策略。现代浏览器需支持 dialog、details、CSS grid、dvh。

## 评审操作顺序

1. 客户页输入任意虚构问题，发送得到固定模拟回复。空白不发送，中文输入法组合期间不会误发；Enter 发送，Shift+Enter 换行。
2. 下方“原型状态演示”切换正常聊天 / 等待人工 / 人工回复。等待时输入禁用；人工回复明确署名。控件只切展示，不生成或回滚工单。
3. 顶部评审控制条进入坐席演示。无需账号密码，勾选虚构数据声明进入。未登录直接打开 inbox/review 会显示模拟登录。
4. 处理台查看左列表、中会话/草稿/编辑器、右侧内部评分和事件。搜索 DEMO-102、客户或问题；切待处理/已处理；输入不存在的词查看空态并清除筛选。筛选不会自动切当前详情。
5. 在 DEMO-101 点击“采纳到编辑器”：编辑器填入内容，但会话不增加人工消息、工单仍待处理。再次采纳且编辑器有内容时须确认覆盖。
6. 修改回复后切换 DEMO-102、进入复盘或退出，出现未保存提示：取消留在原会话；确认才丢弃。客户未发输入切路由/演示状态也有提示；关闭/刷新时由浏览器处理原生离开提醒。
7. 点击“预览并确认提交”，检查对象、编号、最终全文；取消保留编辑，确认才关闭虚构工单。确认期间防重复，已完成后无再次提交入口。
8. 在同一标签通过评审控制条返回客户页，可看到 DEMO-101 的人工回复。DEMO-102/103 不映射该客户窗口。此行为是共享内存演示，不是跨标签实时通讯。
9. 复盘选择工单，核对 classify/quality_check/handoff/suspended 与本次 draft_adopted/human_submitted。它们不是生产审计日志。
10. 人工调整窗口宽度：≥1180px 三栏；761–1179px 右侧依据移动到详情下方并默认折叠；≤760px 客户单列、坐席队列横向滚动、右栏可展开、复盘单列。调整后刷新/重进处理台可恢复该宽度的默认折叠状态。

## 文件职责

- `index.html`：静态入口、虚构数据标识、评审导航、确认弹窗、禁止网络连接的 CSP。
- `styles.css`：企业蓝灰视觉、响应式、焦点样式与对话布局。
- `state.js`：内存 fixture 和工单状态逻辑，方便独立验证。
- `app.js`：四页渲染、hash 路由、输入、确认、防重与未保存提示。
- `prototype.test.cjs`：Node 内置测试，无 npm 包；覆盖采纳不发送、空白/重复提交、切换保护、搜索筛选、状态和事件。

## 局限

无真实登录授权、数据库、模型调用、消息推送、网络失败模拟、工单认领、服务端幂等和持久审计。只在当前标签保存；刷新丢失所有演示内容并退出身份。前端示意守卫不是安全边界。队列 SSE 与客户消息实时投递是不同能力，现有业务的工单 SSE 不提供客户人工消息推送。

本次按要求未使用浏览器，未执行真实点击或视觉/无障碍/手机设备验收；Node 测试仅验证状态逻辑，不代表全部 DOM 与布局通过。上面的操作清单留给人工评审。后续阶段必须重新获得授权再改业务代码。
